# AutoEvolve Interface Audit - 2026-06-07

## Anti-Patterns Verdict

**Verdict: Pass, with cleanup needed.** AutoEvolve does not look like a generic AI landing page. The rendered interface is restrained, source-led, and archive-like, which suits the project identity better than a dramatic marketing treatment would.

The main AI-adjacent tells are subtler:

- The homepage count block in `src/pages/index.astro` resembles the familiar hero-metrics pattern.
- Large one-column card lists appear across route indexes, especially the technology catalogue.
- `src/styles/global.css` carries both the older warm archive palette and the later v1 Shrimp-derived theme layer, which makes the visual system feel patched rather than fully resolved.
- The font stack still leans on common interface defaults: `Avenir Next`, `Helvetica Neue`, `Arial`, `Inter`, and system UI.

The stronger counterweight is that the site uses real sourced media, specific archive routes, compact editorial hierarchy, and neutral technical language. It reads as an educational reference surface rather than a synthetic product brochure.

## Detailed Findings by Severity

### Critical Issues

No critical issues found. Core navigation, route rendering, sourced media, generated page overflow, and homepage automated accessibility all passed current checks.

### High-Severity Issues

#### H1. Search Input Has No Visible Label

- **Location:** `src/pages/search.astro:37-46`
- **Severity:** High
- **Category:** Accessibility
- **Description:** The built Search page loads Pagefind's default UI. Axe reports `label-title-only` because the generated text input uses a placeholder and `title="Search"` but no visible label.
- **Impact:** Screen-reader, speech-input, and cognitive-support workflows receive weaker form context. Placeholder-only search fields are also easier to lose once a user starts typing.
- **WCAG/Standard:** WCAG 3.3.2 Labels or Instructions; axe `label-title-only`.
- **Recommendation:** Add a persistent visible label for the search input, or migrate to Pagefind's Component UI if it gives better accessible labeling and customization. Keep the label consistent with archive language, such as "Search archive".
- **Suggested command:** `/harden` for accessibility behavior, followed by `/polish` for visual integration.

#### H2. Era Timeline Text Fails Contrast During Scroll Animation

- **Location:** `src/styles/global.css:528-530` and `src/styles/global.css:951-969`
- **Severity:** High
- **Category:** Accessibility / Motion
- **Description:** Era summary text normally uses `--color-muted`, but the scroll-linked animation starts `.era-moment` at `opacity: 0.78`. Axe measured several era summaries at a contrast ratio of **3.74:1** against white while the animation state was active.
- **Impact:** Low-vision users can encounter under-contrast body text while reading the timeline. The issue is easy to miss because the final resting color is stronger than the animated state.
- **WCAG/Standard:** WCAG 1.4.3 Contrast Minimum.
- **Recommendation:** Keep timeline text at full opacity throughout the animation and animate only transform, spacing, or a non-text decorative layer. If fading is kept, use a higher starting opacity that preserves at least 4.5:1 effective contrast.
- **Suggested command:** `/animate` to revise the motion pattern, then `/harden` to re-check contrast.

### Medium-Severity Issues

#### M1. Scrollable KaTeX Display Regions Are Not Keyboard Focusable

- **Location:** `src/styles/global.css:645-651` and `src/styles/global.css:665-672`
- **Severity:** Medium
- **Category:** Accessibility
- **Description:** Wide KaTeX display blocks intentionally use `overflow-x: auto`, but the scrollable container is not focusable. Axe reports `scrollable-region-focusable` on `/controversies/dieselgate/`.
- **Impact:** Keyboard-only users can read the page but may be unable to inspect the full horizontal equation if it overflows.
- **WCAG/Standard:** WCAG 2.1.1 Keyboard; axe `scrollable-region-focusable`.
- **Recommendation:** Add keyboard focusability to scrollable math wrappers, with a visible focus state and a concise accessible label where practical. This likely belongs in the markdown or rehype rendering path rather than CSS alone.
- **Suggested command:** `/harden`.

#### M2. System Atlas Uses ARIA Tabs Without the Expected Keyboard Model

- **Location:** `src/components/CarSystemsExplorer.astro:570-579` and `src/components/CarSystemsExplorer.astro:819-823`
- **Severity:** Medium
- **Category:** Accessibility / Interaction
- **Description:** The powertrain selector is marked up with `role="tablist"` and `role="tab"`, but only click handlers are implemented. A targeted probe showed `ArrowRight` did not move selection from "All-electric"; `Tab` moved to the next tab instead.
- **Impact:** Keyboard users can still operate the controls by tabbing through every button, but the interaction does not match the ARIA tab pattern announced to assistive technology.
- **WCAG/Standard:** WAI-ARIA Authoring Practices Guide Tabs pattern; WCAG 4.1.2 Name, Role, Value risk.
- **Recommendation:** Either implement roving `tabindex`, Left/Right arrow navigation, Home/End support, and focus management, or simplify the control to a plain segmented button group without tab roles.
- **Suggested command:** `/adapt` for interaction behavior, followed by `/harden`.

#### M3. Theme Tokens Are Split Across Two Visual Systems

- **Location:** `src/styles/global.css:1-17` and `src/styles/global.css:973-1023`
- **Severity:** Medium
- **Category:** Theming
- **Description:** The stylesheet defines an original warm archive palette, then later remaps the public color tokens through a Shrimp-derived v1 palette. Several later rules also use direct hex and `rgb()` values instead of semantic tokens.
- **Impact:** Future visual changes are more likely to produce inconsistent contrast, duplicated overrides, and stale assumptions. It also makes dark mode or alternate themes harder because not all surface, text, and accent decisions flow through one clear token map.
- **WCAG/Standard:** No direct WCAG violation, but it increases accessibility regression risk.
- **Recommendation:** Collapse the theme into one semantic token layer, keep historical palette notes in a theme reference doc if needed, and replace direct color literals with semantic tokens where the color is part of the design system.
- **Suggested command:** `/normalize`, with `/colorize` if the palette needs a fuller pass.

#### M4. Full-Site Axe Coverage Is Not Yet in the E2E Suite

- **Location:** `tests/e2e/archive.spec.ts:623-627`
- **Severity:** Medium
- **Category:** Accessibility / Testing
- **Description:** The e2e suite runs axe only on the homepage. The targeted audit found serious axe violations on `/search/`, `/eras/`, and `/controversies/dieselgate/` that the existing suite does not catch.
- **Impact:** Accessibility regressions can ship on non-home routes even while the current e2e suite stays green.
- **WCAG/Standard:** Testing coverage risk rather than a direct user-facing violation.
- **Recommendation:** Add representative axe scans for Search, Eras, a math-heavy article, a vehicle page, and a controversy page. Keep the generated-route overflow checks separate so the suite remains fast and readable.
- **Suggested command:** `/harden`.

### Low-Severity Issues

#### L1. Desktop Hotspots Are Smaller Than the 44px Touch Target Guideline

- **Location:** `src/styles/global.css:1509-1525` and `src/styles/global.css:1880-1884`
- **Severity:** Low
- **Category:** Accessibility / Responsive
- **Description:** `.car-hotspot` uses `min-height: 36px` and `min-width: 36px` by default. The mobile breakpoint raises height to 44px, but coarse-pointer tablets and hybrid devices may still receive the smaller desktop target.
- **Impact:** Touch users on wider devices may have a slightly harder time selecting precise system hotspots.
- **WCAG/Standard:** WCAG 2.5.8 Target Size, with exceptions depending on spacing and inline context.
- **Recommendation:** Use `min-height` and `min-width` of 44px on coarse pointers, or make the default target size 44px while preserving the compact visual label.
- **Suggested command:** `/adapt`.

#### L2. Vehicle Index Thumbnails Use Eager Loading and Synchronous Decoding

- **Location:** `src/components/ContentCard.astro:25-31` and `src/pages/vehicles/index.astro:52-68`
- **Severity:** Low
- **Category:** Performance
- **Description:** `ContentCard` thumbnails use `loading="eager"` and `decoding="sync"`. Today this affects a small set of vehicle thumbnails, but the component is reusable and can become expensive if more image-backed lists are added.
- **Impact:** Eager, synchronous image decode can compete with initial rendering and interaction on slower devices.
- **WCAG/Standard:** Performance best practice.
- **Recommendation:** Add an explicit priority prop for above-the-fold images and default repeated card thumbnails to `loading="lazy"` and `decoding="async"`.
- **Suggested command:** `/optimize`.

#### L3. Sticky Header Blur Adds Cost Without Much Product Value

- **Location:** `src/styles/global.css:1047-1051`
- **Severity:** Low
- **Category:** Performance / Anti-pattern
- **Description:** The sticky header uses `backdrop-filter: blur(16px)`. It is restrained, but it is still a glassmorphism-adjacent effect in an otherwise editorial archive UI.
- **Impact:** The effect can add paint/compositing cost and does little to improve comprehension or navigation.
- **WCAG/Standard:** Performance best practice; frontend-design anti-pattern watch item.
- **Recommendation:** Prefer an opaque or near-opaque surface with a border/shadow token. If blur remains, add a fallback and verify it does not create text contrast problems over page media.
- **Suggested command:** `/quieter` or `/optimize`.

#### L4. Footer Links and Brand Link Are Below 44px Tall on Mobile

- **Location:** `src/components/SiteFooter.astro:1-15` and `src/styles/global.css:1131-1150`
- **Severity:** Low
- **Category:** Accessibility / Responsive
- **Description:** The targeted mobile touch probe found footer links around 26px tall and the brand link around 36px tall. These are lower-risk because they are text links with spacing, but they are less comfortable than the primary navigation.
- **Impact:** Users with motor impairments may need more precision when using footer navigation on touch devices.
- **WCAG/Standard:** WCAG 2.5.8 Target Size, with possible inline and spacing exceptions.
- **Recommendation:** Increase vertical padding or line-height for footer links and the brand anchor on small screens without making the footer visually heavy.
- **Suggested command:** `/adapt` or `/polish`.

## Patterns & Systemic Issues

- **Accessibility coverage is uneven.** The homepage is clean under axe, but Search, Eras, and Dieselgate expose issues once representative routes are scanned.
- **Motion and contrast interact.** The era timeline proves that final-state contrast is not enough when text opacity changes during scroll-linked animation.
- **Theming is layered rather than consolidated.** Old tokens, new tokens, direct hex values, and `rgb()` literals coexist in one stylesheet.
- **Responsive structure is generally strong.** No tested route showed page-level horizontal overflow at 320px, 390px, or 1440px.
- **The interface uses many cards, but usually for real repeated archive records.** This is acceptable for an archive; the risk is sameness, not functional confusion.

## Positive Findings

- Static build, unit tests, and e2e tests all passed.
- The e2e suite already checks all generated routes for page overflow and broken sourced media.
- Sourced media has strong alt text, captions, source links, and rights context.
- The homepage skip link and visible focus outline are present.
- Mobile layouts avoid amputating core functionality; the system atlas adapts hotspots into a grid rather than hiding them.
- Mathematical content is intentionally handled with horizontally inspectable KaTeX wrappers.
- The visual tone is restrained and archive-appropriate, not a dark neon dashboard or generic gradient landing page.
